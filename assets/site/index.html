How it works

Your AI talks to Obsidian, not your files

Most Obsidian bridges read your .md files directly from disk. VaultGate doesn't — every operation is delegated to the running Obsidian instance, so your links, backlinks, and plugins always stay consistent.

1

Obsidian runs

Your notes stay inside Obsidian, behind its own application layer. VaultGate never touches the file system directly.

2

VaultGate bridges

A local MCP server binds to 127.0.0.1 only — never exposed to the network, never relayed to the cloud.

3

Your AI connects

Any MCP-compatible client — Joule Work, Claude Code, Cursor, and more — reads and writes your vault in real time.

Features

Everything you need, nothing you don't

Safe by default

All write operations default to dry-run — VaultGate previews what would change before touching a single note.

No plugins required

Built on Obsidian's native integration APIs. No community plugins to install or maintain.

Private by design

Never reads your .md files directly. Every operation goes through Obsidian, and the server binds to 127.0.0.1 only — nothing leaves your machine.

Offline semantic search

Find notes by meaning, not just keywords. Runs the embedding model fully locally — no internet required.

Scope Zones

Partition your vault into named zones and control exactly what the AI can see per session — enforced server-side, never by LLM instruction.

Vault conventions

Teach the AI your vault's structure and habits with a single markdown file — automatically injected at the start of every conversation.
